# Site spec

`site/` is a minimal static browser for this marketplace's catalog, built
with Vite + React + TypeScript, deployed as static files (`site/dist`) with
no backend. All data comes from JSON files generated by
`scripts/build-index.mjs` into `site/public/`.

## Data files (produced by `scripts/build-index.mjs`)

- `site/public/index.json` — the plugin/component catalog (see "Index
  fields" below).
- `site/public/releases.json` — per-plugin version history, read from each
  plugin's `CHANGELOG.md` (one entry per `## [x.y.z]` heading found).
- `site/public/stats.json` — aggregate counts: total plugins, total
  skills, total agents, total eval cases, generated-at timestamp.
- `site/public/bodies/*.md` — one file per plugin/skill/agent, holding the
  raw markdown body (README, SKILL.md content minus frontmatter, agent
  prompt minus frontmatter) for detail-page rendering.

## Routes (hash-based; no server routing required)

| Route | Page |
|---|---|
| `#/` | Home — marketplace name/description, the four plugin cards (name, one-line description, version, component counts), a link into search. |
| `#/search` | Search — a MiniSearch-powered text box over the index; results list matching plugins/skills/agents with a one-line snippet and a link to their detail page. |
| `#/plugin/<name>` | Plugin detail — see "Plugin detail page fields" below. |
| `#/artifact/<id>` | Artifact detail — a single skill or agent's own page. `<id>` is `<plugin>:<kind>:<name>` (e.g. `engineering-paved-path:skill:zod`, `research-tools:agent:researcher`). See "Artifact detail page" below. |
| `#/whats-new` | What's new — the union of all plugins' `releases.json` entries, newest first, each linking to its plugin detail page. |
| `#/getting-started` | Getting started — static page: how to add this marketplace locally, the install command pattern, link to `CONTRIBUTING.md`'s rendered body. |

An unknown hash route renders a "not found" state with a link back to `#/`.

## Index fields (`index.json`)

```ts
type IndexEntry = {
  kind: "plugin" | "skill" | "agent";
  id: string;            // "<plugin>" for a plugin, "<plugin>:<kind>:<name>" for a component
  plugin: string;        // owning plugin name
  name: string;
  description: string;
  version?: string;      // plugin.json version, plugins only
  keywords: string[];
  dependencies?: string[]; // plugin.json dependencies, plugins only ("name@range" strings)
  bodyPath: string;      // path under site/public/bodies/ holding the full markdown body
  searchText: string;    // name + description + keywords + full body content, lowercased,
                          // concatenated for MiniSearch to index
};
type Index = { generatedAt: string; entries: IndexEntry[] };
```

## Search behavior

- MiniSearch indexes `name`, `description`, `keywords`, and `searchText`
  (which embeds each entry's full README/SKILL.md/agent-prompt body) across
  all entries in `index.json`, with `name`/`description`/`keywords`
  weighted higher than the full-body `searchText` field.
- Prefix matching and a small fuzzy-edit-distance allowance are both
  enabled (MiniSearch's `prefix: true`, `fuzzy: 0.2`), so a partial or
  slightly misspelled query still surfaces relevant results.
- Results are grouped by `kind` in the UI (Plugins, then Skills, then
  Agents) rather than interleaved by raw relevance score, so a search for
  a generic term like "zod" doesn't bury the `zod` skill itself under
  agents that happen to mention it in passing.

## Plugin detail page fields (`#/plugin/<name>`)

- Name, version (from `plugin.json`), owner/author.
- Compatibility floor (from that plugin's `COMPATIBILITY.md`, parsed for
  its `Claude Code: >= x.y.z` line — shown verbatim if parsing finds
  nothing structured).
- Dependencies, each rendered as a link to that dependency's own
  `#/plugin/<name>` page plus the declared semver range.
- Component list: every skill and agent the plugin ships, each linking to
  its `#/artifact/<id>` page.
- Install command, shown verbatim and copyable:
  `/plugin install <name>@dev-digest-ai-marketplace`.
- Rendered body: the plugin's `README.md`, converted from markdown via
  `marked` and sanitized via `DOMPurify` before insertion (plugin content
  is repository data, not site code — never trust it unsanitized).
- A "Releases" section listing that plugin's entries from `releases.json`.

## Artifact detail page fields (`#/artifact/<id>`)

- Kind (Skill or Agent), name, owning plugin (linked back to
  `#/plugin/<name>`).
- For an agent: its declared `tools`, `model`, and any `skills:` frontmatter
  list (each entry linked to its own `#/artifact/<id>` if it resolves to a
  known skill in the index).
- For a skill: its `name`/`description` frontmatter, and a list of any
  sibling files under its directory (e.g. `rules/*.md`, `examples.md`)
  noted as "supporting files" (not separately rendered unless the body
  itself links to them).
- Rendered body: the component's markdown body (SKILL.md content below the
  frontmatter, or the agent prompt below its frontmatter), via the same
  `marked` + `DOMPurify` pipeline as the plugin detail page.

## Install-command display

Everywhere an install command is shown (home page plugin cards, plugin
detail page, getting-started page), it is rendered in a `<code>` block with
a copy-to-clipboard button, using the exact form
`/plugin install <plugin-name>@dev-digest-ai-marketplace` — never a
shortened or paraphrased version, since that string is meant to be pasted
directly into Claude Code.
